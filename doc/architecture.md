# KCP 协议架构深度分析

## 1. 项目概述

KCP (Kinetic Communication Protocol) 是一个快速可靠的 ARQ (Automatic Repeat reQuest，自动重传请求) 协议实现，由林伟 (skywind3000) 于 2011 年创作。

### 1.1 核心特性

| 特性 | 说明 |
|------|------|
| **低延迟** | 相比传统 ARQ (如 TCP)，平均 RTT 降低 30%-40%，最大延迟降低 3 倍 |
| **轻量级** | 仅两个源文件 (ikcp.h, ikcp.c)，总计约 1300 行 C 代码 |
| **无系统调用** | 内部没有任何系统调用，所有时钟由外部传入 |
| **传输无关** | 不负责底层协议收发，通过回调机制与下层协议解耦 |
| **可定制** | 支持自定义内存分配器、日志系统、工作模式等 |

### 1.2 设计理念

KCP 的设计哲学是将协议栈 **"拆开"**，提供可自由组合的 "协议单元"：

```
┌─────────────────────────────────────────────┐
│           应用层 (Application)                │
├─────────────────────────────────────────────┤
│  KCP 可靠传输 (ikcp.c/h)   ← 核心协议单元    │
├─────────────────────────────────────────────┤
│  FEC (可选)  Reed-Solomon 纠删码              │
├─────────────────────────────────────────────┤
│  加密层 (可选)  RC4/Salsa20 流加密            │
├─────────────────────────────────────────────┤
│  UDP 传输层 (用户自定义)                       │
└─────────────────────────────────────────────┘
```

### 1.3 TCP vs KCP 对比

| 维度 | TCP | KCP |
|------|-----|-----|
| 设计目标 | 吞吐量优先 | 延迟优先 |
| RTO 增长 | ×2 (指数增长) | ×1.5 (快速模式下) |
| 重传策略 | 全部重传 | 选择性重传 |
| 快速重传 | 依赖重复 ACK 数量 |  configurable |
| ACK 策略 | 延迟 ACK (默认) | 可配置即时/延迟 ACK |
| 流控 | 标准退让 | 可关闭 |
| 带宽代价 | 低 | 高 10%-20% |

### 2.2 数据流方向

#### 发送路径 (Up → Down)

```
用户数据
  │
  ▼
ikcp_send() ──► 分段/流合并 ──► snd_queue ──► ikcp_flush() ──► snd_buf
                                                                      │
                                                              (编码输出)
                                                                      │
                                                              ikcp->output()
                                                                      │
                                                                   UDP
```

#### 接收路径 (Down → Up)

```
UDP 包
  │
  ▼
ikcp_input() ──► 头部解析 ──► 验证 conv ──► 分类处理
                                                    │
                            ┌───────────┬───────────┬──────────┐
                            ▼           ▼           ▼          ▼
                          ACK        PUSH        PROBE       WINS
                            │           │                     │
                            │      ┌────▼────┐                │
                            │      │ rcv_buf │                │
                            │      └────┬────┘                │
                            │           │                      │
                            │      ┌────▼────┐                │
                            │      │rcv_queue│                │
                            │      └────┬────┘                │
                            └──────────┼──────────────────────┘
                                       │
                               ikcp_recv()
                                       │
                                    用户数据
```

## 4. 内部链表实现

KCP 使用类似 Linux 内核的双向循环链表实现队列，完全不依赖标准库：

### 4.1 链表头

```c
struct IQUEUEHEAD {
    struct IQUEUEHEAD *next, *prev;
};
```

### 4.2 核心操作

| 操作 | 宏/函数 | 说明 |
|------|---------|------|
| 初始化 | `IQUEUE_HEAD_INIT(name)` | 编译期初始化 |
| 初始化 | `iqueue_init(ptr)` | 运行期初始化 |
| 添加头部 | `iqueue_add(node, head)` | 插入到 head 之后 |
| 添加尾部 | `iqueue_add_tail(node, head)` | 插入到 head 之前 |
| 删除 | `iqueue_del(entry)` | 从链表中移除 |
| 删除并初始化 | `iqueue_del_init(entry)` | 删除后重新初始化 |
| 判空 | `iqueue_is_empty(entry)` | 检查链表是否为空 |
| 获取入口 | `iqueue_entry(ptr, type, member)` | 从链表节点获取包含结构体 |

### 4.3 四个队列的作用

```
snd_queue: 用户通过 ikcp_send 提交的数据，按顺序排列
rcv_queue: 已按序重组的数据，用户通过 ikcp_recv 读取
snd_buf:   已发送但未被 ACK 确认的数据，用于重传
rcv_buf:   已接收但未按序的数据，用于乱序缓存
```

## 5. 生命周期

### 5.1 对象生命周期

```
ikcp_create()
    │
    ├── 分配 IKCPCB 结构
    ├── 初始化所有成员为默认值
    ├── 分配输出缓冲区 (MTU+OVERHEAD)*3
    ├── 初始化四个双向链表
    └── 返回 ikcpcb*
    │
    ▼
[正常工作阶段]
    │
    ├── 定期调用 ikcp_update()
    ├── 收到数据调用 ikcp_input()
    ├── 发送数据调用 ikcp_send()
    ├── 接收数据调用 ikcp_recv()
    └── 配置参数使用各配置函数
    │
    ▼
ikcp_release()
    │
    ├── 清空 snd_buf 并释放所有段
    ├── 清空 rcv_buf 并释放所有段
    ├── 清空 snd_queue 并释放所有段
    ├── 清空 rcv_queue 并释放所有段
    ├── 释放输出缓冲区
    ├── 释放 acklist
    └── 释放 IKCPCB 自身
```

## 6. 线程安全

**KCP 内部不是线程安全的**。在多线程环境下，用户需要自行保证：

1. 对同一个 `ikcpcb` 对象的访问需要加锁
2. `output` 回调函数需要保证线程安全
3. 建议在单线程事件循环中使用，避免锁竞争

## 7. 内存模型

### 7.1 内存布局

```
ikcpcb 自身 (约 200+ 字节)
  │
  ├── buffer 输出缓冲区 (默认 4632 字节 = (1400+24)*3)
  │
  └── acklist 动态扩容 (从 8 开始，2倍增长)
       │
       ├── IKCPSEG 段对象 (24 + data_size 字节)
       │    ├── 段头部 (24 字节)
       │    └── 数据区 (可变长度)
       │
       └── 所有段通过双向链表连接
```

### 7.2 内存管理可定制

通过 `ikcp_allocator()` 可以替换整个内存分配器：

```c
// 示例：使用内存池
void* my_malloc(size_t size) { return pool_alloc(size); }
void  my_free(void* ptr)      { pool_free(ptr); }

ikcp_allocator(my_malloc, my_free);
```

## 8. 总结

KCP 是一个设计精良的轻量级可靠传输协议实现，其核心优势在于：

1. **极简架构** - 两个文件，代码量小，易于理解和集成
2. **高度解耦** - 与底层传输完全分离，仅通过回调通信
3. **无系统调用** - 所有时钟由外部传入，便于嵌入式和模拟环境
4. **灵活可配** - 多种模式切换，参数可调
5. **高效实现** - 纯 C 实现，无动态分配热路径，内存管理优化

这些特性使得 KCP 特别适用于对延迟敏感的游戏、实时通信等场景。
